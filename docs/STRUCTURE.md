# Repository structure and architecture

| Path | Responsibility |
| --- | --- |
| `homebrew/main.cpp` | Native title entry, controller lifecycle, settings persistence and HTTP routes |
| `homebrew/native-gpu.*` | GPU worker ownership, start/stop state and synchronized snapshots |
| `homebrew/native-web.*` | Bounded nonblocking LAN HTTP server |
| `homebrew/native-config.hpp`, `native-options.hpp`, `native-gpu-options.hpp` | Validation and controller setting models |
| `homebrew/native-dashboard.hpp`, `native-ui-font.hpp`, `native-logo.hpp` | TV renderer, baked glyphs and shared logo |
| `homebrew/web/` | Local editor HTML, CSS and JavaScript |
| `homebrew/vendor/` | QR encoder and Bitstream Vera font sources/notices |
| `ps5/c29/` | Vulkan shaders, native C29 engine, cycle solver, probes and container recipe |
| `ps5/manager.*`, `ps5/pool.*` | Job lifecycle, target/share handling, SOCKS5 and GPU TLS transport |
| `ps5/third-party/` | nlohmann/json with MIT notice |
| `sycl/`, `xmrig/` | Retained MO-Miner algorithm sources and support code; combined app uses C29/cycle and Blake2 subsets, not a SYCL runtime |
| `patches/` | Patches applied to pinned upstream XMRig/libuv |
| `scripts/` | Dependency setup, builds, packaging and development helpers |
| `payload/` | Legacy payload and optional metadata refresh helper |
| `tests/` | Host HTTP, input, memory, GPU lifecycle and drawing tests |

| `upstream/`, `toolchain/`, `build/` | Downloaded checkouts, SDK and generated objects; ignored |
| `dist/`, `logs/` | Generated release files and private development evidence; ignored |

## Runtime

One native title (`PPSA99531`) hosts XMRig's CPU core and C29's Vulkan GPU engine. Each has an independent pool connection. The UI thread renders snapshots; a GPU worker owns the transport, job manager and Vulkan objects. Stop is cooperative between completed GPU batches. A GPU fence timeout blocks restart until relaunch to avoid reusing resources with uncertain ownership.

RADV's platform wrappers supply the shared native memory/thread ABI. Portable C29 Blake2 symbols are renamed to avoid colliding with XMRig SIMD dispatch. The combined title excludes the payload mmap/syscall layer and links the working native `sceNet` DNS resolver. These details explain why a desktop XMRig binary cannot simply be copied into the app.

## Build stages

1. `setup.sh`: pin/fetch CPU/framework sources, checksum SDK archive, apply patches.
2. `setup-gpu.sh`: pin GPU/TLS sources, compile GLSL, build the LLVM 18 Linux container, cross-build RADV and generate link metadata.
3. `build-homebrew.py`: build CPU core, native UI and GPU adapter; combine ELF objects; convert/sign the homebrew SELF; stage metadata, starter configs, assets and licenses.
4. `build-release.py`: verify manifest digests and placeholder settings, package app ZIP/source TAR/checksums.

`VALIDATION.md` and `benchmark.md` contain historical development measurements. They do not certify a later commit. `test-combined.py`, `validate-*.py`, `debug-native-ui.py`, `benchmark-native.py` and `refresh-title-metadata.py` are developer tools that may transfer files, change settings, start mining or update metadata on a console; read them before use. CI never deploys to a console.
